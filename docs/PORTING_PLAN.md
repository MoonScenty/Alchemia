# 포팅 계획

대상: Thaumcraft 1.8.9-5.2.4 (클래스 910개) → Alchemia (Minecraft 1.21.1, NeoForge 21.1)

## 참고 자료 준비

원본, 디컴파일 결과, 매핑 도구(`tools/remap_srg.py`)는 모두 저장소 밖(`Desktop/thaumref`)에 둔다.

```bash
cd ~/Desktop/thaumref
# 1. 디컴파일 (Vineflower — NeoForge 빌드를 한 번 돌리면 Gradle 캐시에 들어 있음)
java -Xmx3G -jar <vineflower.jar> --only=thaumcraft Thaumcraft-1.8.9-5.2.4.jar decompiled
# 2. MCP 매핑
git clone --depth 1 https://github.com/Marcelektro/MCP-919
# 3. SRG → MCP 이름 치환
python tools/remap_srg.py MCP-919/conf decompiled/thaumcraft src/thaumcraft
```

결과: 910개 파일, 이름 54,409개 치환, 698개 미매핑(대부분 Forge 추가분·람다 파라미터).

## 포팅 순서

각 단계는 그 자체로 빌드·실행 가능한 상태로 끝낸다.

- [x] **0. 프로젝트 정리** — 템플릿 제거, 패키지 구조, 참고 자료 준비
- [x] **1. 기반 자원** — datagen 구성 완료 (`./gradlew runData`)
  - [x] A. 광석·결정: 호박/진사 광석(+심층암), 결정 7종(4단계), 조각 7종+균형 조각, 진사 원석, 군집 4종, 제련 레시피, 월드젠
    - 결정의 성장·전파·플럭스 오염은 오라에 의존하므로 5단계에서 구현. 지금은 생성된 크기 그대로 유지된다.
    - 바이옴별 결정 편향(원본 `BiomeHandler`)은 2단계 이후.
    - 군집 입수 경로(원소 곡괭이, 도가니 정제)는 9·7단계에서.
  - [x] B. 금속·기본 재료: 알케미움/황동 블록·주괴·조각·톱니바퀴·판, 철 판, 수은 방울, 살리스 문두스, 9개 압축/해체·판·톱니바퀴 조합법
    - 알케미움·황동 주괴 제작(도가니)은 7단계. 살리스 문두스는 **균형 조각을 구우면** 나온다(원본과 동일, 6단계에서 추가).
  - [x] C. 나무 2종: 거대나무·은빛나무의 원목/판자/잎/묘목/계단/반 블록, 묘목 성장, 자연 생성, 조합법, 가연성·퇴비화
    - 거대나무: 2×2 줄기(높이 12~22)에 위로 뻗는 가지, 가지 끝과 꼭대기에 잎 뭉치. 숲·평원·초원·늪에 약 14청크당 1그루.
    - 은빛나무: 十자 줄기(높이 7~10)에 뿌리·옹이, 세로로 긴 둥근 수관. 원목은 밝기 6. 자작나무 숲·꽃 숲·`c:is_magical` 바이옴에 약 40청크당 1그루.
    - 잎 드롭: 거대나무 묘목 1/44, 은빛나무 묘목 1/200 + 수은 방울 1/100 (행운 적용).
    - 미구현: 은빛나무 안의 오라 노드(5단계), 거미가 사는 거대나무 변형(11단계), 화분에 심은 묘목.
    - `runGameTestServer`로 두 나무가 실제로 생성되는지 검사한다 (`gametest/WorldgenTests`).
  - [x] D. 식물 3종: 반짝잎·재진주·비스버섯, 파티클, 비스버섯 접촉 시 멀미, 자연 생성, 증류 조합법
    - 반짝잎·비스버섯은 은빛나무와 함께 생성된다 (`UndergrowthDecorator`). 원본은 비스버섯을 마법 숲 바이옴에 심었으므로, 13단계에서 바이옴이 생기면 그쪽으로 옮긴다.
    - 재진주는 사막·악지에 약 30청크당 한 무리.
    - 파티클은 바닐라로 대체했다 (반짝잎 `end_rod`, 재진주 `smoke`+`flame`, 비스버섯 보라색 `dust`). 원본의 위습 파티클은 14단계에서.
    - 조합법: 반짝잎 → 수은, 재진주 → 블레이즈 가루 (원본과 동일하게 1:1).
  - [x] E. 석재·장식: 신비한 돌·신비한 돌 벽돌(각각 계단·반 블록), 호박 블록·호박 벽돌
    - 비전 석재 자체는 비전 작업대로 만든다(돌 8 + 조각 1 → 9개, terra 5 + ignis 5). 6C에서 추가했다.
    - 호박 블록·벽돌은 원본대로 서로 2×2로 오갈 수 있고, 반투명이며 맨손으로 캐진다. 신호기 기반 블록이다.
    - 스톤커터 레시피는 1.21 관례에 맞춰 추가했다 (원본에는 없음).
- [x] **2. 상 시스템**
  - [x] A. 상 레지스트리: 상 35종(원시 6 + 합성 29). 원본처럼 코드에 정의하는 정적 커스텀 레지스트리(`alchemia:aspect`)이므로 부가 모드도 같은 방식으로 등록할 수 있다. ID는 원본의 라틴어(`alchemia:aer`).
    - 색상 35개와 블렌딩은 원본 값 그대로. 조합 역방향 조회(aer+perditio → vacuos)는 레지스트리에서 자동으로 만든다.
    - 아이콘 35장은 game-icons.net(Lorc, CC BY 3.0). 배경·미발견 2장은 자체 제작. [CREDITS.md](../CREDITS.md) 참고.
    - 이름은 모든 언어에서 라틴어로 두고, 뜻은 `.description`에 적는다 (원본과 같은 방식).
  - [x] B. `AspectList`: 불변 상→개수 맵. Codec/StreamCodec, 합산·차감·배율·상한, 이름순·양순 정렬.
    - `cull()`은 6종까지 줄인다. 합성 깊이가 깊을수록 가중치를 올려, 양이 비슷하면 복잡한 상이 남는다.
  - [x] C. 아이템·엔티티 → 상: NeoForge 데이터맵 `alchemia:aspects` (아이템 104항목, 엔티티 21항목). 태그를 키로 쓸 수 있어 `#c:ingots/iron` 한 줄이 모든 철 주괴를 덮는다.
    - 원본 469줄을 다 옮기지 않고 **원재료와 몹만** 적었다. 만들어지는 물건은 D가 알아서 계산한다. 다른 모드 아이템도 같은 경로로 처리된다.
    - 1.21 추가분(구리·자수정·심층암)은 원본에 대응이 없어 새로 정했다.
  - [x] D. 레시피 기반 상 유추 (`aspect/Aspects.java`): 데이터맵에 없으면 레시피를 거슬러 올라가 재료 상을 합산하고 ×0.75 ÷ 결과 개수. 순환 방지, 깊이 32, 상한 64, 마지막에 `cull()`.
    - 양쪽이 각자 계산한다. 레시피와 데이터맵 모두 클라이언트로 동기화되므로 별도 패킷이 필요 없다.
    - 예: 철 곡괭이 = 주괴 3(metallum 4씩) + 막대 2(herba 1씩) → metallum 9, herba 1.
    - 속성 보너스(`aspect/AspectBonuses.java`): 도구→instrumentum(등급+1), 검→aversio(등급+1), 활→aversio 3+volatus 1, 방어구→praemunio(방어력), 인챈트 38종→해당 상, 인챈트 레벨 합계→potentia. 원본처럼 합산이 아니라 최댓값으로 병합한다.
    - 인챈트는 스택별이라 `of(ItemStack)`에서만 더해지고 캐시하지 않는다. `of(Item)`은 아이템 종류 보너스까지만 캐시한다.
    - [x] **부어 넣은 에센시아도 센다** (7·8단계가 끝나고 붙였다): 도가니 레시피는 녹아 있던 상을, 주입 레시피는 마신 에센시아를 재료와 함께 더한다. 재료만 세면 공허 씨앗이 성질 고약한 밀 씨앗으로 읽힌다 — 그것에게 일어난 일은 전부 물속에서 일어났다.
      - 비전 작업대의 비스는 일부러 뺀다. 오라에서 나와 오라로 돌아가는 것이라, 물건이 무엇으로 되어 있느냐가 아니라 작업대를 돌리는 값이다.
      - **에센시아를 문 레시피를 먼저 묻는다.** 도가니에서 끓일 수 있는 물건은 대개 제 너깃 아홉으로도 뭉칠 수 있는데, 그 두 번째 길은 물건에 대해 아무것도 말해 주지 않는다. 너깃으로 거슬러 올라간 알케미움 주괴는 그냥 쇠붙이로 나온다.
  - [x] E. 슬롯 위 상 아이콘 오버레이 (`client/AspectOverlay.java`). 원본과 같이 **고글 없이 Shift**로 표시되며, 설정 `alwaysShowAspects`로 뒤집을 수 있다.

      - 테고리는 그림의 밝기를 그대로 두고 색상과 채도만 간다. 막대는 그럴 수 없다 — 그림이 연한 나무 두 톤(테두리 0.2, 몸통 0.95, 사이 없음)이라 밝기를 두면 여덟이 똑같이 밝아지고 흑요석이 연보라가 된다. 몸통은 재료 제 중간·밝은 톤을 쓰고 테두리는 가장 어두운 톤을 더 눌러 선으로 남긴다 (`tools/gen_cap.py`, `tools/gen_rod.py`).
      - 나무 막대는 낱개 아이템이 없다. 그냥 막대기다.
    - 완드에 깔리는 옛 그림 두 벌(`rod_X`, `cap_X`)은 `tools/gen_wand.py`가 그린 채로 남아 있다. 입체 모형이 쓰지 않으니 지워도 되는 자리다.

      - **여섯이 다르게 생겼다** (2026-09-28, MoonScenty 제작). 원본은 여섯이 같은 모형이지만, 가운데만 바꾸면 한눈에 구별되는 것을 굳이 같게 둘 이유가 없다. 팔과 목테는 여섯이 같이 쓰고 가운데만 다르다.

      - **밸브 손잡이는 렌더러가 그린다.** 블록 상태는 미리 적어 둔 모형 중에서 고르기만 하는데, 이 바퀴에서 돌았음이 보이는 각도는 45°이고 모형은 이미 45°로 앉은 모서리를 더 돌릴 수 없다(상자 하나에 회전 하나, 허용 각도 ±22.5°·±45°). 코드에서는 각도가 그냥 숫자라 **아무 각도나 되고, 여닫는 동안 스르륵 돈다.** 원본도 이 방식이다(`TileTubeValve.rotation`).
      - 그래서 밸브만 제 블록 개체를 쓴다. 언제 만졌는지를 **세상 시계의 한 순간으로** 적어 두고, 그리는 쪽이 거기서 얼마나 돌았는지를 계산한다. 세는 숫자를 보내면 매번 다시 보내야 하지만 순간은 한 번 보내면 그만이다.
      - 역류방지의 화살표는 **가리키는 쪽에 연결이 있을 때만**, 제한의 띠는 **연결된 면마다** 그린다. 팔이 없는 면에 그리면 허공에 뜬다.
      - 여과관은 **걸어 둔 상의 색으로 물든다.** 은나무 판자가 흰 계열이라 색칠 자리를 얹으면 그대로 받는다.
      - 훑어 올라가는 길에서 관마다 셋을 묻는다: 지나갈 수 있는가, 상을 하나로 고집하는가, 몇 턴 기다리게 하는가. 판단은 전부 그 답으로 한다.
      - 여과기에 상을 거는 것은 **유리병이나 원시 조각**이다. 원본은 유리병만 쓰는데, 조각이 먼저 손에 들어오니 그쪽도 받는다. 조각은 원소 여섯과 플럭스뿐이고 유리병은 서른다섯이 다 된다. 웅크리고 누르면 잊는다.
      - **원본과 다른 점**: 원본의 제한관은 흡입력을 절반으로 깎는다. 여기엔 흡입력이 없으니 한 턴 쉬는 것으로 같은 몫을 만든다.
      - 여과기 둘이 서로 다른 상을 걸고 한 줄에 있으면 아무것도 지나가지 않는다. 특례를 두지 않고 그대로 답한다.
      - 완충기는 **다른 완충기에서 가져오지 않는다.** 나란히 두면 한 점을 영원히 주고받기만 한다.
      - 밸브는 열림과 **직전 레드스톤 값**을 둘 다 블록 상태에 적는다. 방금 들어온 신호와 계속 있던 신호를 구별해야, 손으로 돌려 둔 것이 레드스톤 갱신마다 되돌아가지 않는다.
      - 밸브·역류방지·제한은 답을 블록 상태에 적으니 블록 개체가 기억할 것이 없다. 평범한 관과 **한 종류를 같이 쓴다.**
    - [x] 유리병: 한 병에 상 하나를 여덟 점. **여덟이 아니면 아무 일도 없다** — 일곱 든 그릇은 병을 채우지 못하고, 일곱 자리 남은 그릇은 병을 받지 못한다. 모자라게 옮겨진 것은 도로 돌려놓는다. 빈 병이면 뜨고 든 병이면 따르니, 사람이 방향을 고를 일이 없다.
      - 액체는 MoonScenty가 그린 아홉 컷짜리 애니메이션이고, 완전한 무채색이라 상 색을 그대로 입는다. 유리 윤곽을 앞에 두어 다섯 칸 겹치는 자리를 윤곽이 덮는다.
    - [x] 라벨: 붙이면 단지가 **그 상만 받는다. 비어 있어도 그대로다.** 빈 선반을 먼저 늘어놓고 나중에 채울 수 있게 하는 것이 요점이다. 백지는 단지가 이미 든 것을 따라 적고, 미리 적어 둔 것은 빈 단지에 붙는다. 웅크리고 맨손으로 누르면 떼어진다.
      - 적기와 지우기는 코드로 쓴 레시피다. 백지와 든 병을 같이 놓으면 적히고, **병은 비어서 돌아온다.** 라벨이 지니는 것은 양이 아니라 이름이니 에센시아가 닳을 이유가 없다. 적힌 것을 혼자 놓으면 지워진다.
      - 붙인 면은 붙일 때 서 있던 쪽이다. 읽을 쪽에서 붙게 된다.
    - **결정화된 에센시아**(8B에서 만든 `crystallized_essence`)는 이것들과 다른 물건이다. 상 하나를 담는 서른다섯 색짜리 아이템이고, 여기서 말하는 조각은 원시 결정에서 캐는 `alchemia:shards` 쪽이다. 이름을 원본대로 쓴 이유가 있다 — "비스 결정"으로 두면 담긴 것을 따라 "공기 결정"이 되어 노드에 자라는 블록과 이름이 겹친다.
    - [x] 단지 고정대: 물리면 **넣을 수는 있고 뺄 수는 없다.** 원본에서는 주입 제단이 단지를 빨아먹지 못하게 막는 물건이고, 8단계 전까지는 관과 유리병이 빼가지 못하게 막는 것으로 쓴다. 부수면 라벨과 함께 도로 나온다.
    - [x] 증류 가지 연구 넷과 레시피 열넷: `distillation`(여과망·제련로·증류기) → `jar_label`(단지·유리병·라벨·고정대), `tubes`(관·밸브) → `tube_filter`(여과·제한·역류방지·완충). 값과 모양은 원본 그대로다.
      - 원본이 아홉 너깃 중 다섯째로 적은 관 레시피의 재료는 **수은 너깃**이다.
  - [x] **7D. 공허 금속** — 밀 씨앗 → (도가니) → 공허 씨앗 → (도가니) → 공허 주괴. 6C에서 미룬 공허 캡이 여기서 열린다.
    - 값은 원본 그대로. 씨앗은 tenebrae 8·vacuos 8·alienis 2, 주괴는 metallum 7·**vitium 1**. 깨끗한 물에서는 굳지 않는다 — 이 금속은 제 안에 잘못된 것을 원한다.
    - 공허 캡은 조각 다섯으로 만든다. 값은 다른 캡과 같은 규칙(`craftCost × 8`)이라 네 원소에 각 72씩, 지금까지 중 가장 비싸다.
    - 텍스처는 절차적으로 짰다(`tools/gen_void.py`). **공허 색은 우리 공허 완드 캡에서 읽어 온다** — 모드 안에 공허 색이 있는 곳이 거기뿐이고, 그래야 캡과 주괴가 한 금속으로 보인다.
      - 주괴와 조각은 **우리 알케미움 것에서 빛을 읽어 공허 색으로 되칠한 것**이다. 모양과 명암은 MoonScenty 것이고 물감만 바뀐다. 새로 그리지 않으면 셋이 같은 쪽에서 빛을 받는다.
      - 씨앗은 기하다. **테두리가 가장 밝고 가운데가 꺼지는 구슬** — 빛을 먹는다는 말이 되고, 이만큼 어두운 그림이 슬롯에서 읽히는 유일한 방법이기도 하다. 네 단으로 끊었다.
      - 금속은 캡보다 0.62배 어둡다. 캡은 갈아 낸 끝이라 빛을 모으고, 덩어리는 먹는다. 둘이 같은 광을 내면 안 된다.
- [x] **8. 주입 제단** — 멀티블록, 불안정성, 주입 레시피/인챈트 (13단계 돌이 필요한 것만 남았다)
  - [x] **8A. 제단과 받침대** — 룬 결계와 비전 받침대. 완드로 깨우고, 다시 찍어 시작하고, 한 바퀴에 20틱.
    - 받침대는 **한 번에 하나만** 든다. 받침대에 주괴 셋이 올라가면 하나 올라간 것과 똑같이 보이고, 그 뒤로 고리를 세는 일이 전부 거짓말이 된다. 든 것은 떠서 돈다 — 도는 값은 블록마다가 아니라 세상 시계에서 가져와야 고리가 같이 돈다.
    - 결계는 **블록 모형이 없다.** 보이는 것은 전부 렌더러가 한 틱씩 그린다. 움직임이 곧 그 물건이라 멈춘 그림은 거짓말이 된다. 큐브 하나를 여덟 번 그리고, 각각 90°씩 다르게 돌려 같은 여섯 룬이 서는 자리마다 다르게 읽히게 한다.
    - **완드로 두 번 찍는다.** 첫 번째는 제단을 깨운다 — 기둥이 그려지고 돌이 돌기 시작한다. 그 뒤로는 찍을 때마다 일이 시작된다. 깨우는 것은 건물에 한 번 하는 일이고 시작하는 것은 매번 하는 일이라, 방금 둘 중 무엇을 했는지 말해 주지 못하는 제단은 나쁜 제단이다.
    - **귀퉁이는 비전 석재 두 칸씩이다.** 네 귀퉁이(두 칸 아래 대각선)에 두 칸씩 쌓고 완드로 찍으면 여덟 칸이 전부 **아무것도 그리지 않는 블록**으로 바뀌고, 결계가 그 자리에 기둥을 그린다. 부수면 비전 석재로 돌아온다.
      - **기둥이 두 칸짜리니 귀퉁이도 두 칸이다.** 원본 제단이 그 모양이고 그림도 그 높이로 그려져 있다. 한 칸으로 줄이면 다른 건물이다.
      - 돌을 그대로 두고 그 위에 그려도 봤는데, 기둥 발이 블록 아래 절반만 덮어서 돌 윗절반이 기둥 옆으로 삐져나온다. **통짜 블록은 뾰족한 것 뒤에 숨지 않는다.**
    - **한 군데라도 빠지면 그리기를 멈춘다.** 귀퉁이 돌은 결계의 이웃이 아니라 부서져도 아무도 알려 주지 않으니, 1초에 한 번 제 밑을 돌아본다. 하나로 충분해야 한다 — 하나 부수고 아무 일도 없으면 왜 그런지 알아보려고 하나를 더 부순다.
    - **받침대 하나와 귀퉁이 돌 넷이 없으면 아무 일도 하지 않는다** (원본 `validLocation`). 일하는 도중에 무너뜨리면 하던 일이 끝나고 결계도 도로 잠든다.
    - 고리는 **한 기둥에 받침대 하나**. 가로 8칸, 아래로 10칸까지 본다. 쌓아 둔 받침대는 열 곳이 아니라 한 곳이다.
    - 에센시아는 **12칸 안 단지에서 관 없이 곧장 빨아 온다** (원본과 같다). 공방은 배관하는 것이 맞지만 제단은 열두 단지에서 한 점씩 당기는 물건이라, 열두 줄기를 한 블록에 꽂는 매듭을 만들 이유가 없다. **고정대를 문 단지는 건너뛴다** — 고정대가 바로 그 뜻이다.
    - 한 바퀴에 **빚진 상마다 한 점씩** 마시고, 다 갚으면 고리를 하나씩 먹는다. 고리가 비면 아래 받침대의 것이 결과로 바뀐다.
    - **불안정은 대칭에서 나온다.** 받침대 하나마다 값이 붙고(물건이 올라가 있으면 더), **결계를 지나 같은 거리 반대편**에 같은 받침대가 있으면 그만큼 상쇄된다. 짝을 지어 깔면 레시피 값 그대로고, 하나를 끝에 매달면 전체가 떨기 시작한다. 방 모양이 아니라 **결계를 기준으로 한 대칭**이라, 어떤 방에 지어도 규칙은 하나다 — 양쪽을 같이 지을 것.
      - **안정화 블록**: 해골과 촛대를 **결계 양쪽에 짝지어** 두면 불안정이 깎인다. 하나만 두면 오히려 붙는다 — 한쪽에만 놓인 해골은 장식이 아니라 도는 물건 한쪽에 붙은 혹이다. 10분의 1 단위로 세고 정수로 잘라내니 촛대 두엇은 값이 없고, 한 점을 깎으려면 짝지은 해골 열 쌍이 든다. 고리를 제대로 깐 다음에 마지막으로 집는 물건이지 처음에 집는 물건이 아니다. 무엇이 여기 드는지는 `alchemia:stabilises_infusion` 태그가 정한다.
      - 깨어 있고 일하지 않을 때 결계를 맨손으로 찍으면 고리가 고른지, 붙들려 있는지 말해 준다. **시작하기 전이 고칠 수 있는 유일한 때다.**
    - **불안정**은 레시피 값에 대칭 값을 더한 것에서 시작해 최대 25. 한 바퀴에 `nextInt(500) <= 불안정`이면 사고가 난다. 다섯 종류(물건 튕겨내기·번개·상처·폭발·뒤틀림) 중 하나고, **사고마다 불안정이 1씩 는다.** 나쁘게 시작한 일은 더 나빠지는 쪽으로 간다. 제단을 제대로 깔고 시작할 이유가 그것이다.
    - 아무것도 터뜨리지 않는다. 공방이 제 지붕을 태우면 배우는 것이 없다.
    - 막대 일곱 종(흑요석·얼음·석영·갈대·블레이즈·뼈·은나무)이 여기서 열린다. 6C에서 미뤄 둔 것이다. 값은 원본대로 주재료 두 배, 성격 하나씩. 은나무만 모든 것에 하나씩이고, 그게 은나무인 이유다.
  - [x] **8B. 값과 빠르기, 캡, 마법부여**
    - [x] **주입석 둘** — 제단 귀퉁이보다 한 켜 아래(`y−3`)에 까는 돌. 속도석은 한 바퀴 `−2`틱에 값 `+0.01`, 절약석은 `+1`틱에 `−0.02`. 넷을 같은 것으로 깔면 한 바퀴 20→**12틱**이거나 값이 **8%** 싸지고, 섞어 깔 수도 있다. 무엇을 깔아도 **반값 아래로는 안 내려간다**(원본이 그은 선).
      - 작업대 레시피다. `SNS/NGN/SNS`(비전 석재·니토르·황금 블록), `SAS/AGA/SAS`(비전 석재·알루멘툼·황금 블록). 연구 `infusion_boost`. **니토르와 알루멘툼이 여기서 필요해져서 7A에 붙였다.**
      - 값은 **100분의 1 단위 정수로** 센다. 실수로 들면 저장과 불러오기를 오갈 때마다 어긋난다. 깎다가 한 점이 안 되는 상은 빠진다(원본과 같다).
      - **한 번만 읽는다.** 일이 시작될 때 읽고 그 뒤로는 보지 않으니, 도중에 돌을 갈아 끼워도 시작할 때의 값으로 간다. 고리와 불안정이 이미 그 규칙이다. 일이 끝나면 20과 100으로 돌아간다.
      - 표식을 새기고 새긴 자리를 물들였다. 가까이서는 갈매기와 마름모가, 멀리서는 따뜻한 빛과 차가운 빛이 어느 쪽인지 말한다. 제단 밑에 깔아 두고 다시 안 건드리는 물건이라 멀리서 읽혀야 한다. 끌은 룬 돌들이 쓰는 것과 같다 (`tools/gen_matrix_stones.py`).
    - [x] **알케미움·공허 캡을 두 단계로** — 작업대는 불활성 주조물을 만들고 제단이 완성한다. 값은 원본대로: 알케미움은 살리스 셋에 불안정 5(`potentia 12 · auram 6`), 공허는 넷에 8(`potentia/vacuos/alienis/auram 각 18`). 주조물 그림은 완성된 캡에서 색기를 빼고 한 단계 어둡게 한 것이다 — 원본은 완성된 것이 세 컷으로 일렁여서 구별하는데, 정지 그림에서는 광으로 대신할 수밖에 없다 (`tools/gen_inert_caps.py`).
    - [x] **주입 마법부여** — 작업대가 팔지 않는 것을 제단이 도구에 얹는다. 운도 없고 담아 둘 책도 없다.
      - 어디에 붙는지는 **아이템 태그**로 적는다. 원본은 도구에게 제 부류를 물었는데, 1.8.9가 같은 질문을 할 수 있는 방식이 그것이었다. 태그면 다른 모드 도구도 그냥 걸린다.
      - 데이터 컴포넌트 `infusion_enchantments`는 `Map<종류, 단계>`다. 같은 것을 두 번 걸면 옆에 붙는 것이 아니라 깊어지고, 갈 데까지 간 도구는 그대로 돌아온다 — **제단은 같은 한 걸음을 두 번 팔지 않는다.**
      - `InfusionRecipe`에 `enchants` 칸을 하나 더했다. 그 칸이 적혀 있으면 결과는 들어간 물건에 한 단계가 얹힌 것이고, 제단은 적힌 결과를 읽는 대신 레시피에게 물어본다. 흐름 코덱은 조각이 일곱이라 손으로 썼다(합치는 도구가 여섯에서 멈춘다).
      - 툴팁은 아이템이 아니라 이벤트에서 쓴다. 바닐라 곡괭이는 우리를 모른다.
      - **여섯 종**: 수집(부순 것이 부순 이에게 — 안 들어가면 그 자리에 떨어진다), 파괴(때린 면 기준 둘레 여덟, 그 도구로 캘 수 있는 것만, 칸마다 내구도 1), 굴착(광맥·줄기를 먼 끝에서부터. 줄기 2칸·광맥 1칸, **이어진 것**만), 탐지(돌을 두드리면 광석 자리에 파티클, 두드린 사람에게만, 내구도 5), 전이(옆에 선 것에도 같은 매, 단계 수만큼, 길들인 것과 사람 제외), 정수(죽인 것이 제 상을 조금 내놓는다).
      - **캐는 것들은 웅크리면 꺼진다.** 자세가 아니라 **키**를 묻는다 — 자세는 틱을 돌아야 잡히고, 두 칸 틈에 낀 채로 키를 눌러도 한 칸만 캐자는 뜻은 통해야 한다.
      - 번지는 것 셋(파괴·굴착·전이)에 재진입 잠금이 있다. 전이는 잠그지 않으면 좀비 떼에 한 번 휘두르는 것으로 스택이 넘친다.
      - **결정화된 에센시아**를 여기서 만들었다(`crystallized_essence`). 정수가 떨굴 것이 없었다 — 상을 담는 물건이 유리병(8점)뿐이고 조각은 원시 여섯뿐이다. 무채색 49픽셀 한 장에 상 색을 입혀 서른다섯이 난다. 원본 이름을 그대로 쓴다: "비스 결정"으로 두면 노드에 자라는 결정 블록과 이름이 겹친다.
      - **원본과 다른 점**: 고리에 올라가는 지식의 파편이 13단계 전리품이라 **연구 노트**로 대신한다. 수집은 원본이 아이템을 날려 보내 줍게 하는데, 가방에 바로 넣는다 — 결과가 같고 1초 빠르다.
      - **미구현**: 정련(정제)은 10단계 굴착기가 읽어야 값이 생긴다. 신속·민첩·감염은 원본에도 레시피가 없다. 비스 전지·비스 충전은 원본에서 이름만 있고 레시피도 읽는 곳도 없는 미완성 자리다.

    - **발목을 기준으로 다리에 맞춘다.** 다리를 감싸는 것이 발목이니 그것이 다리 위에 와야 한다. 신발 전체 가운데로 맞추면 다리가 발 한복판에 박히고 신 목이 뒤로 물러선다.

  - [ ] **9D. 로브** — 천 로브 셋과 공허 로브 셋. 메시로 입는 첫 방어구다.

    - **슬롯에도 같은 메시를 그린다**(`builtin/entity` + BEWLR). 평평한 그림을 따로 그렸다면 한 점을 두 번 그리는 셈이고 다시 그리는 첫날 어긋난다. 크기는 구워진 면에서 직접 재어 슬롯 한가운데 세운다.

    - **메시는 사 온 것이라 저장소에 없다**(`.gitignore`). `tools/gen_robe.py --install`로 제자리에 놓는다.

    - **메시와 시트는 사 온 것이라 저장소에 없다**(`.gitignore`). `tools/gen_fortress.py --install`로 제자리에 놓는다.
    - **남은 것**: 레시피(주입, 알케미움 갑옷을 가운데 두고), 연구, 그리고 하는 일 — 한 벌을 갖출수록 세지는 것(한 점마다 12.5%), 피해 종류를 가리는 것(마법은 덜, 불과 폭발은 더), 낙하로는 닳지 않는 것, 투구에 고글과 가면 넷을 달 수 있는 것. 바닐라 방어구 셈에 끼어들던 부분은 이 판에 그대로 옮길 수 없어 다시 설계해야 한다.
  - [ ] **9C. 포커스** — 열둘. **아이템 등록까지 했다. 쏘는 것은 아직이다.**
    - 원본은 포커스마다 클래스가 하나였다. 클래스가 값과 **하는 일**을 같이 지고 있었기 때문이다. 여기서는 값만 `Focus` 레코드로 떼어 내고 아이템은 하나로 뒀다 — 값·색·재사용 대기·포탑 가능 여부는 열둘이 같은 모양이고, 하는 일은 열둘이 저마다 다른 곳에 가 붙는다.
    - 값은 전부 원본 그대로다. 불 `불 2`(틱당), 서리 `물 2·불 1·혼돈 2`(200), 충격 `공기 8`(250), 발굴 `흙 1`(틱당), 갈고리 `물 10·공기 10`(250), 아홉 지옥 `불 10·혼돈 5·공기 5`(1000), 펙의 저주 `흙 2·혼돈 2·물 2`(250), 이동식 구멍 `혼돈 25·공기 25·흙 25`, 원시 `여섯 각 10`(500), 비스 조각 `불 1·혼돈 1·공기 1`(300), 등가교환 `혼돈 1·흙 1·질서 1`, 건설 `공기 1·흙 1·질서 1`. 괄호는 밀리초 단위 대기다.
    - **값을 무는 방식이 둘이다.** 불과 발굴만 누르고 있는 동안 틱마다 물고, 나머지 열은 쏠 때 한 번 문다. 이 깃발을 뒤집으면 이동식 구멍이 초당 예순 번 값을 문다.
    - **원시의 값은 흔들린다.** 원본은 여섯에 각각 `10 + rand(0..4)*2`를 물리고 그 난수를 0.2초마다 다시 뽑는다. 툴팁이 떨리고 실제 청구액도 매번 달랐다. 여기에는 **10만 넣었다.** 흔들림은 무는 쪽의 일이고 아직 무는 것이 없다 — 값을 실제로 청구하는 자리가 생길 때 되돌린다.
    - **여섯 원시를 하나씩 적는다.** `ModAspects.primals()`는 상 레지스트리를 읽는데, 이 코드는 아이템 레지스트리가 채워지는 동안 돈다. 그때 상 레지스트리는 비어 있다. 홀더는 채워지기 전에도 가리킬 수 있지만 홀더 **목록**은 셀 수 없다.
    - **주머니 칸은 태그로 묻는다**(`alchemia:foci`). 원본은 `ItemFocusBasic` 인스턴스인지 물었다. 태그로 물으면 애드온의 포커스도 우리 것을 상속하지 않고 주머니에 들어간다.
    - 이름은 원본 그대로다. 몇은 하는 일을 말하지 않지만(펙의 저주는 무엇을 거는지가 아니라 누구에게 배웠는지로 붙은 이름이다) 분명하게 고쳐 부르는 것은 남의 주문 이름을 고치는 것이다.
    - **완드에 끼우는 것까지 했다.** 기본 V, 웅크리고 V면 뺀다.
      - **원본은 F였고 그 시절엔 비어 있던 키다.** 이 판에서는 바닐라의 손 바꾸기다. 한 키에 걸린 두 바인딩은 둘 다 발동하므로 누르면 포커스가 바뀌면서 손도 바뀐다. V는 비어 있고 같은 손에 닿는다.
      - 원본은 F를 **누르고 있으면** 가진 포커스가 둥글게 펼쳐지고 놓는 자리의 것이 끼워진다. 여기서는 한 번 누르면 다음 것으로 넘어간다. 고르는 방식은 고르는 일 위에 얹는 것이라, 바퀴는 나중에 이 아래를 건드리지 않고 올릴 수 있다.
      - **순서는 가방 자리가 아니라 이름순이다.** 가방을 정리했다고 다음에 올 포커스가 바뀌면 안 된다. 끝까지 가면 처음으로 돌아오므로, 포커스를 하나만 가진 사람은 같은 키로 끼웠다 뺐다 한다.
      - **끼우는 것은 옮기는 것이다.** 원래 끼워져 있던 것은 새것이 빠져나온 그 칸에 들어간다. 빈 것이 확실한 유일한 칸이다. 원본은 가방 아무 데나 넣었는데, 결과는 같고 가방이 덜 어질러진다.
      - **끼운 포커스는 아이템 하나로 저장한다.** 종류만 적으면 업그레이드가 붙는 순간 같은 종류의 두 포커스를 구분할 수 없다. 다만 컴포넌트는 불변이고 값으로 비교되어야 하는데 `ItemStack`은 둘 다 아니라 등록이 거부된다 — 한 칸짜리 `ItemContainerContents`에 담는다. 셜커 상자 속을 담는 그 상자에 하나만 넣은 것이다.
      - **무엇이 끼워졌는지는 완드가 말한다.** 툴팁 한 줄과, 바꿀 때 단축바 위에 뜨는 글이다. 원본은 조준점 옆에 포커스 그림을 띄워 두는데 그것은 HUD고 HUD로 써야 한다.
      - 패킷은 "다음 것" 또는 "빼기"만 보낸다. 어느 포커스인지는 보내지 않는다 — 가방을 아는 것은 서버고 클라이언트의 사본은 한 틱 늦을 수 있다. 완드도 패킷이 아니라 손에서 집는다.
    - **주머니까지 했다.** 열여덟 칸, 여섯 곱하기 셋. 우클릭으로 연다.
      - **담긴 것은 아이템에 있다.** 블록이 아니니 세상에 둘 자리가 없다. 칸은 사본이고 무엇이 움직일 때마다 아이템에 다시 적는다. 상자보다 자주 적는 셈이지만 담는 것이 열여덟뿐이고, 안 그러면 옮기는 도중에 게임을 끈 사람이 가방을 잃는다.
      - **빈 주머니는 컴포넌트를 아예 지운다.** 빈 것으로 가득 찬 컴포넌트를 들고 있으면 새 주머니와 겹쳐지지도 같다고 비교되지도 않는다. 아무도 못 보는 차이이면서 다들 걸려 넘어지는 종류다.
      - **열려 있는 동안 그 주머니는 못 움직인다.** 가방에서 그 칸을 못으로 박는다. 주머니를 제 안에 밀어 넣거나, 떨어뜨려 놓고 빈 창을 들여다보는 일이 없다.
      - **완드는 주머니 안도 뒤진다.** 그것이 주머니의 값어치다 — 가방에서 열여덟 칸을 내주지 않고도 키 하나에 모든 포커스가 걸린다. 뺀 포커스도 가방이 아니라 빈 주머니 칸으로 돌아간다.
      - 레시피는 원본 그대로 `LGL / LBL / LLL`(가죽·금 주괴), 값은 `흙 25·질서 25·혼돈 25`다. **원본과 다른 점**: 가운데가 평범한 허리띠인데 그것은 장신구이고 아직 없다. 허리띠를 이루는 것(가죽에 황동 주괴)을 대신 넣었다 — 둘레가 이미 가죽 일곱이라 **황동 주괴**만 가운데 놓으면 된다.
    - **남은 것**: 열둘이 각각 하는 일, 업그레이드 스물셋, 포탑, 고르는 바퀴. 쏘는 것이 가장 큰 덩어리이고 열둘이 서로 별로 닮지 않았다.

## 미결 사항

- **에셋**: 원본 텍스처/모델/사운드는 쓸 수 없다. 텍스처가 필요한 항목은 단계마다 목록을 만들어 MoonScenty에게 확인받은 뒤 진행한다.
- **미발견 상 가리기** (2026-09-20 결정, 원본과 다름): 원본은 Shift만 누르면 모든 상이 그대로 보이고 연구와 무관하다. Alchemia는 **아이템은 항상 보이되, 아직 발견하지 못한 상은 물음표(`textures/aspect/unknown.png`)로 가린다.**
  - 아이템 단위가 아니라 상 단위(35종)로 잠그므로, 아이템마다 스캔할 필요 없이 스캔할수록 세상이 선명해진다.
  - 검토했으나 택하지 않은 방식: 원본 그대로 두기 / 스캔한 아이템만 보이기 / 알케모노미콘 보유 시 해금.
- **TC4와 섞지 않는다** (2026-09-23 결정): TC4는 vis를 노드에서 거리 감쇠로 직접 뽑아서 노드 옆에 공방을 지는 것이 의미 있었고, TC5는 청크 오라라 그 감각이 약하다. 그래도 **TC5 그대로 간다.**
  - 육각 격자 퍼즐은 TC4.2에서 들어왔고 TC5가 물려받은 것이다. TC5가 바꾼 건 퍼즐이 아니라 Research Point 경제를 없앤 것뿐이다.
  - 두 모드를 실제로 합치려면 TC4를 다시 디컴파일해야 하고(매핑 다름) aspect·research API가 서로 안 맞는다. 얻는 것에 비해 비용이 크다.
  - 나중에 마음이 바뀜면 모드 합치기가 아니라 **상수 조정**으로 된다: 청크 간 확산을 느리면 노드 거리가 충전 속도를 지배하고, 거기에 Node in a Jar를 더하면 TC4의 감각이 나온다. 청크 오라는 저절로 회복하지 않고 노드만이 채우므로 토대는 이미 있다.
