# 포팅 계획

대상: Thaumcraft 1.8.9-5.2.4 (클래스 910개) → Alchemia (Minecraft 1.21.1, NeoForge 21.1)

## 참고 자료 준비

원본, 디컴파일 결과, 매핑 도구(`tools/remap_srg.py`)는 모두 저장소 밖(`Desktop/thaumref`)에 둔다.

```bash
cd ~/Desktop/thaumref
# 1. 디컴파일 (Vineflower — NeoForge 빌드를 한 번 돌리면 Gradle 캐시에 들어 있음)
java -Xmx3G -jar <vineflower.jar> --only=thaumcraft Thaumcraft-1.8.9-5.2.4.jar decompiled
# 2. MCP 매핑
git clone --depth 1 https://github.com/Marcelektro/MCP-919
# 3. SRG → MCP 이름 치환
python tools/remap_srg.py MCP-919/conf decompiled/thaumcraft src/thaumcraft
```

결과: 910개 파일, 이름 54,409개 치환, 698개 미매핑(대부분 Forge 추가분·람다 파라미터).

## 포팅 순서

각 단계는 그 자체로 빌드·실행 가능한 상태로 끝낸다.

- [x] **0. 프로젝트 정리** — 템플릿 제거, 패키지 구조, 참고 자료 준비
- [x] **1. 기반 자원** — datagen 구성 완료 (`./gradlew runData`)
  - [x] A. 광석·결정: 호박/진사 광석(+심층암), 결정 7종(4단계), 조각 7종+균형 조각, 진사 원석, 군집 4종, 제련 레시피, 월드젠
    - 결정의 성장·전파·플럭스 오염은 오라에 의존하므로 5단계에서 구현. 지금은 생성된 크기 그대로 유지된다.
    - 바이옴별 결정 편향(원본 `BiomeHandler`)은 2단계 이후.
    - 군집 입수 경로(원소 곡괭이, 도가니 정제)는 9·7단계에서.
  - [x] B. 금속·기본 재료: 알케미움/황동 블록·주괴·조각·톱니바퀴·판, 철 판, 수은 방울, 살리스 문두스, 9개 압축/해체·판·톱니바퀴 조합법
    - 알케미움·황동 주괴 제작(도가니)은 7단계, 살리스 문두스 제작(신비한 작업대)은 6단계에서. 지금은 크리에이티브 전용.
  - [x] C. 나무 2종: 거대나무·은빛나무의 원목/판자/잎/묘목/계단/반 블록, 묘목 성장, 자연 생성, 조합법, 가연성·퇴비화
    - 거대나무: 2×2 줄기(높이 12~22)에 위로 뻗는 가지, 가지 끝과 꼭대기에 잎 뭉치. 숲·평원·초원·늪에 약 14청크당 1그루.
    - 은빛나무: 十자 줄기(높이 7~10)에 뿌리·옹이, 세로로 긴 둥근 수관. 원목은 밝기 6. 자작나무 숲·꽃 숲·`c:is_magical` 바이옴에 약 40청크당 1그루.
    - 잎 드롭: 거대나무 묘목 1/44, 은빛나무 묘목 1/200 + 수은 방울 1/100 (행운 적용).
    - 미구현: 은빛나무 안의 오라 노드(5단계), 거미가 사는 거대나무 변형(11단계), 화분에 심은 묘목.
    - `runGameTestServer`로 두 나무가 실제로 생성되는지 검사한다 (`gametest/WorldgenTests`).
  - [x] D. 식물 3종: 반짝잎·재진주·비스버섯, 파티클, 비스버섯 접촉 시 멀미, 자연 생성, 증류 조합법
    - 반짝잎·비스버섯은 은빛나무와 함께 생성된다 (`UndergrowthDecorator`). 원본은 비스버섯을 마법 숲 바이옴에 심었으므로, 13단계에서 바이옴이 생기면 그쪽으로 옮긴다.
    - 재진주는 사막·악지에 약 30청크당 한 무리.
    - 파티클은 바닐라로 대체했다 (반짝잎 `end_rod`, 재진주 `smoke`+`flame`, 비스버섯 보라색 `dust`). 원본의 위습 파티클은 14단계에서.
    - 조합법: 반짝잎 → 수은, 재진주 → 블레이즈 가루 (원본과 동일하게 1:1).
  - [x] E. 석재·장식: 신비한 돌·신비한 돌 벽돌(각각 계단·반 블록), 호박 블록·호박 벽돌
    - 신비한 돌 자체는 원본에서 신비한 작업대로 만든다(돌 8 + 조각 1 → 9개, 비스 소모). 6단계까지는 크리에이티브 전용.
    - 호박 블록·벽돌은 원본대로 서로 2×2로 오갈 수 있고, 반투명이며 맨손으로 캐진다. 신호기 기반 블록이다.
    - 스톤커터 레시피는 1.21 관례에 맞춰 추가했다 (원본에는 없음).
- [x] **2. 상 시스템**
  - [x] A. 상 레지스트리: 상 35종(원시 6 + 합성 29). 원본처럼 코드에 정의하는 정적 커스텀 레지스트리(`alchemia:aspect`)이므로 부가 모드도 같은 방식으로 등록할 수 있다. ID는 원본의 라틴어(`alchemia:aer`).
    - 색상 35개와 블렌딩은 원본 값 그대로. 조합 역방향 조회(aer+perditio → vacuos)는 레지스트리에서 자동으로 만든다.
    - 아이콘 35장은 game-icons.net(Lorc, CC BY 3.0). 배경·미발견 2장은 자체 제작. [CREDITS.md](../CREDITS.md) 참고.
    - 이름은 모든 언어에서 라틴어로 두고, 뜻은 `.description`에 적는다 (원본과 같은 방식).
  - [x] B. `AspectList`: 불변 상→개수 맵. Codec/StreamCodec, 합산·차감·배율·상한, 이름순·양순 정렬.
    - `cull()`은 6종까지 줄인다. 합성 깊이가 깊을수록 가중치를 올려, 양이 비슷하면 복잡한 상이 남는다.
  - [x] C. 아이템·엔티티 → 상: NeoForge 데이터맵 `alchemia:aspects` (아이템 104항목, 엔티티 21항목). 태그를 키로 쓸 수 있어 `#c:ingots/iron` 한 줄이 모든 철 주괴를 덮는다.
    - 원본 469줄을 다 옮기지 않고 **원재료와 몹만** 적었다. 만들어지는 물건은 D가 알아서 계산한다. 다른 모드 아이템도 같은 경로로 처리된다.
    - 1.21 추가분(구리·자수정·심층암)은 원본에 대응이 없어 새로 정했다.
  - [x] D. 레시피 기반 상 유추 (`aspect/Aspects.java`): 데이터맵에 없으면 레시피를 거슬러 올라가 재료 상을 합산하고 ×0.75 ÷ 결과 개수. 순환 방지, 깊이 32, 상한 64, 마지막에 `cull()`.
    - 양쪽이 각자 계산한다. 레시피와 데이터맵 모두 클라이언트로 동기화되므로 별도 패킷이 필요 없다.
    - 예: 철 곡괭이 = 주괴 3(metallum 4씩) + 막대 2(herba 1씩) → metallum 9, herba 1.
    - 속성 보너스(`aspect/AspectBonuses.java`): 도구→instrumentum(등급+1), 검→aversio(등급+1), 활→aversio 3+volatus 1, 방어구→praemunio(방어력), 인챈트 38종→해당 상, 인챈트 레벨 합계→potentia. 원본처럼 합산이 아니라 최댓값으로 병합한다.
    - 인챈트는 스택별이라 `of(ItemStack)`에서만 더해지고 캐시하지 않는다. `of(Item)`은 아이템 종류 보너스까지만 캐시한다.
    - 미구현: 도가니·주입 레시피 유추는 7·8단계에서.
  - [x] E. 슬롯 위 상 아이콘 오버레이 (`client/AspectOverlay.java`). 원본과 같이 **고글 없이 Shift**로 표시되며, 설정 `alwaysShowAspects`로 뒤집을 수 있다.

## 미결 사항

- **에셋**: 원본 텍스처/모델/사운드는 쓸 수 없다. 텍스처가 필요한 항목은 단계마다 목록을 만들어 MoonScenty에게 확인받은 뒤 진행한다.
- **미발견 상 가리기** (2026-09-20 결정, 원본과 다름): 원본은 Shift만 누르면 모든 상이 그대로 보이고 연구와 무관하다. Alchemia는 **아이템은 항상 보이되, 아직 발견하지 못한 상은 물음표(`textures/aspect/unknown.png`)로 가린다.**
  - 아이템 단위가 아니라 상 단위(35종)로 잠그므로, 아이템마다 스캔할 필요 없이 스캔할수록 세상이 선명해진다.
  - 검토했으나 택하지 않은 방식: 원본 그대로 두기 / 스캔한 아이템만 보이기 / 알케모노미콘 보유 시 해금.
- **명칭**: 원본 이름의 `thaum`은 `alche`로 바꾼다 (규칙은 PORTING_CONVENTIONS.md). 그 외 이름(상, 장치 등)은 원본 명칭을 따르되 단계별로 확인한다.
